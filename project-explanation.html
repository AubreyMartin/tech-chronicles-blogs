📰 Project Overview

Tech Chronicles

A role-based blog management system built with React JS, JSON Server, and Bootstrap 5.

In Development
01 — Overview

Tech Chronicles is a multi-role blogging platform where users can browse and read technology articles, authors manage their own posts, and admins oversee the entire content pipeline. The frontend is a React single-page application; the backend is a mock REST API powered by JSON Server, making it easy to prototype without a real database.

In production / static builds the app falls back to reading a bundled /db.json file so it can be hosted on any static host (Vercel, Netlify, GitHub Pages) without a running server.

04 — Client-Side Routing

All routes are defined in src/App.jsx using React Router DOM's <BrowserRouter>.

Path Component Description
/ HomePage Landing page with a welcome message and navigation links.
/all-blogs AllBlogsPage Paginated list of all blogs with live category and author filters.
/blog/:id BlogDetail Single blog view. The :id param is used to fetch the specific post.
/BlogDetail BlogDetail Legacy alias route (no id param — renders "Blog not found").

// src/api/blogs.js — smart environment switcher
const API_BASE = import.meta.env.VITE_API_URL;

export async function fetchBlogs() {
  if (API_BASE) {
    const res = await axios.get(`${API_BASE}/blogs`);
    return res.data;           // live JSON Server
  }
  return getStaticBlogs();    // fallback: /db.json
}
06 — Component Breakdown

HomePage.jsx

Simple landing page. Renders a welcome heading and two <Link> elements pointing to /all-blogs and /BlogDetail. No local state — purely presentational.

AllBlogsPage.jsx

Fetches all blogs on mount via fetchBlogs() and stores them in state. Derives unique categories and authors from the data. Two <select> dropdowns drive live filtering. Renders a list of clickable blog titles, each a <Link to="/blog/:id">.

State: blogs[] · category · author

BlogDetail.jsx

Reads the :id URL param via useParams() and calls fetchBlog(id) to load a single post. Handles three states: loading spinner, "Blog not found" fallback, and the full post view showing title, author, category, and content.

State: blog · loading

AuthorDashboard.jsx & AdminDashboard.jsx

Both are currently empty stub files — placeholders for the next development phases. They are not yet wired into the router.

09 — How to Run
  1. 1
    Install dependencies
    npm install
  2. 2
    Start the mock API — serves public/db.json as a REST API on port 3000
    npm run server
  3. 3
    Start the Vite dev server — opens at http://localhost:5173
    npm run dev
  4. 4
    (Optional) Build for production — outputs to dist/
    npm run build

Environment Variables
VITE_API_URL
Base URL for the JSON Server API (e.g. http://localhost:3000). When unset (production), the app reads /db.json directly.
